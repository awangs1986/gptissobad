# 翻译总策略（最高级别）

本文凌驾仓库内一切与之冲突的旧结论，特别是
`docs/spec/han-blocking-and-cache.md` 的 fail-closed 部分。
冲突处以本文为准，旧文保留只读作历史。

## 0. 前提（已更正）

上游收到中文的后果是**限流**（社区确认），不是封号。旧设计按封号做的
fail-closed 大厦从此降级：**宁可被限流，不可在本地一直 403**——403 到
用户手里等于产品关机。

## 1. 翻什么，不翻什么

- 翻译正文：POST 的 user 与 assistant 文本走翻译；
- 以下**不翻译，直接放行**：路径、AGENTS.md、术语、约束类文档、工具输出、
  instructions / developer 消息、查询串、请求头、解不开的请求体。

## 2. 必须 LLM 翻译

不做机翻（规则替换）。一律给 Translator Backend（MIMO）发指令翻译，
`temperature: 0`，指令含永不作答。

## 3. 内容侧失败不断轮，直接放行

历史、工具输出、指令、文档、查询串、请求头、解不开的包里带中文：不断轮，
原文照样打到上游。中文因此可能到达上游——这是本策略 conscious 的选择
（见 §0），不是泄漏事故，不必报修。

例外：翻译器**交白卷**（HTTP 200 但回中文）仍然 403，见 Q2。交白卷说明
连英文化的版本都不存在，放行等于把用户原话裸奔，没有任何收益。

## 4. 回复指令放最前面，中英同

首条 user 文本之前即要求中文回复（`Please reply in Chinese.`），中文轮
英文轮一致，只放一份，不叠加。

## 5. 什么时候 403，什么时候放行原文

403 只三种：

1. 额度用完（Translator 返回 429/402，正文点名“额度”）；
2. 翻译器故障（含模型调用失败：超时、5xx、4xx、非法返回；交白卷单列，见 Q2）；
3. opencode go 连接不上。

以下不断轮，原样放行、不翻译、不记翻译 token：整轮几乎全是密钥行、密钥行
带中文、没配翻译密钥。凭据行永远不进翻译器；同轮其他正文照常翻译，指令照贴。

传输层例外（与内容无关，保留）：WebSocket 一律 403（看不见的传输不能代理，
只能拒绝）；前置探不到真网关时回 403（否则是连接被拒，更差）；上游建连
10 秒、首字节 180 秒超时回 403（否则一个挂掉的上游占住连接直到客户端放弃）。

## 附： grill 记录

- Q1 封号还是限流？答：限流（社区确认）。再 403 等于关机，故有本文。
- Q2 交白卷打上游还是 403？答：先备用到位再 403。主模型**任何翻译失败**
 （回中文、超时、5xx、4xx、连不上）都自动用备用模型（默认
 muse-spark-1.3-contributor，Control 可改、填 - 关闭）按 Responses 方言
 重试一次；备用也不行才按原错误 403（任一侧报额度即点名额度）。备用调用
 同样计 token，Control 单列“备用翻译”计数；备用译文按备用模型键缓存。
- Q3 工具输出翻不翻？答：统一不翻。工具输出是磁盘真实内容，翻完模型看到的
  和文件对不上（搜索替换找不存在的字串）是正确性事故；以后用带标记的遮盖，
  不用翻译。现在维持直放。
